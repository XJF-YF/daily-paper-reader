## 摘要
最近的基于查询的前馈3DGS方法使用可学习查询表示场景，每个查询聚合多视图证据并解码一组高斯。理想情况下，不同的查询应专门处理场景中连贯的局部区域。然而，我们观察到从同一查询解码出的高斯通常散布在遥远的场景区域，导致查询级空间连贯性较弱，且与场景结构的对齐不佳。我们将此行为归因于现有高斯查询的纯潜在表示。为解决这一局限，我们引入LocusGS，为每个高斯查询增加一个由中心和支持半径组成的3D锚点状态。该锚点状态在解码器层间逐步细化，并贯穿查询交互、多视图特征聚合和高斯生成。具体而言，锚点到射线的几何偏置引导每个查询关注空间相关的图像观测，而锚点中心解码将其高斯组织在局部区域内。在新视图合成基准上的实验表明，在相同高斯预算下，LocusGS相较于基于查询的高斯标记基线提升了渲染质量。进一步分析显示，学习到的锚点形成连贯的空间布局，并产生更有结构的高斯分布，证明显式锚点状态改善了空间组织。我们的项目页面：https://leo-frank.github.io/LocusGS_viewer。

## Abstract
Recent query-based feed-forward 3DGS methods represent a scene using learnable queries, each aggregating multi-view evidence and decoding a group of Gaussians. Ideally, different queries should specialize in coherent local regions of the scene. However, we observe that Gaussians decoded from the same query often scatter across distant scene regions, resulting in weak query-level spatial coherence and poor alignment with the scene structure. We attribute this behavior to the purely latent representation of existing Gaussian queries. To address this limitation, we introduce LocusGS, which augments each Gaussian query with a 3D anchor state consisting of a center and a support radius. The anchor state is progressively refined across decoder layers and is used throughout query interaction, multi-view feature aggregation, and Gaussian generation. Specifically, an anchor-to-ray geometric bias guides each query toward spatially relevant image observations, while anchor-centered decoding organizes its Gaussians within a local region. Experiments on novel view synthesis benchmarks show that LocusGS improves rendering quality over query-based Gaussian token baselines under the same Gaussian budget. Further analysis shows that the learned anchors form coherent spatial layouts and lead to more structured Gaussian distributions, demonstrating that explicit anchor states improve the spatial organization. ## 论文总结：LocusGS: Spatially Grounded Tokens for Feed-Forward 3D Gaussian Splatting

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：前馈3D高斯泼溅（Feed-forward 3DGS）旨在直接从稀疏输入视图预测3D场景表示，避免逐场景的昂贵优化。其中，基于查询（Query-based）的方法使用一组固定的可学习查询（Tokens），每个查询通过Transformer解码器聚合多视图特征，并解码为一组高斯原语（Gaussians），从而将高斯预算与图像分辨率和输入视图数解耦。
- **核心问题**：现有查询式方法中的每个查询仅由**纯隐式（latent）特征**表示，缺乏显式的空间定位。这导致从同一查询解码出的高斯往往**在空间中分散在相距很远的区域**，而非集中在连贯的局部区域内，从而产生弱的查询级空间相干性，以及全局高斯分布与场景结构对齐不佳的问题。
- **核心含义**：作者指出，隐式查询不明确说明其“在3D中哪里操作”或“覆盖多大区域”，使得多视图证据的聚合和高斯的生成均不受局部空间约束。这种空间特异性的缺失是限制查询式前馈3DGS重建质量的关键因素。

### 2. 方法论：核心思想、关键技术细节与公式

**核心思想**：通过为每个查询增加一个**显式的3D锚点状态（Anchor State）**，将其从隐式的潜在嵌入转变为**空间接地的重建查询**。锚点状态由三维中心 `μ` 和支撑半径 `r` 构成，在解码器层间逐步细化，并用于引导特征聚合与高斯生成，从而将每个查询的高斯限制在局部空间内。

**关键技术细节**：

- **显式3D锚点状态**：每个查询 `i` 在层 `l` 的锚点定义为 `a_i^l = (μ_i^l, r_i^l)`。其中 `μ_i^l ∈ R^3` 为锚点中心，`r_i^l ∈ R+` 为支撑半径（经 `softplus` 激活保证正值：`r = softplus(ρ) + ε`）。
- **锚点感知自注意力（Anchor-Aware Self-Attention）**：将锚点中心的位置编码 `p_i^l = MLP(PE(μ_i^l))` 注入到查询特征中（`q̃_i^l = q_i^l + p_i^l`），使得查询间的交互依赖于它们的空间位置，而非仅依赖于潜在特征。
- **锚点到射线交叉注意力（Anchor-to-Ray Cross-Attention）**：通过几何偏置引导查询聚合与锚点位置空间一致的多视图证据。对于图像标记 `j` 的相机射线 `ℓ_j`，计算锚点中心到该射线的最近欧氏距离 `D(μ_i^l, ℓ_j)`，并定义几何偏置：
  `b_ij^l = -1/2 * (D(μ_i^l, ℓ_j) / (σ₀ * r_i^l))²`
  该偏置加到标准内容注意力 logits 上，软加权选择靠近锚点的图像区域。
- **动态锚点细化（Dynamic Anchor Refinement）**：每个解码层后，通过轻量预测头（`f_μ`, `f_ρ`）根据更新的查询特征预测锚点中心与半径的残差更新，逐步细化锚点状态。
- **锚点中心高斯解码（Anchor-Centered Gaussian Decoding）**：最终层解码时，预测的高斯中心不再是自由预测的，而是以最终锚点中心为参考，由**局部偏移**加上**半径缩放**得到：
  `μ_{i,k}^G = μ_i^L + r_i^L * δ_{i,k}`
  这强制同一查询解码出的高斯集中在锚点周围的局部区域。
- **多层渲染监督**：不仅监督最终层，还对选定的中间解码层（如第6层和第12层）施加渲染损失与可见性正则化，以约束中间锚点细化的过程。

### 6. 论文的主要结论与发现

- **空间接地的有效性**：为查询配备显式3D锚点状态能显著提升查询式前馈3DGS的重建质量。在相同的高斯预算下，LocusGS在RE10K和DL3DV上均优于TokenGS基线，并在多个设置下超越像素对齐方法（如MVSplat、DepthSplat）。
- **结构化空间组织**：LocusGS促使每个token解码的高斯基元在空间中更紧凑、更集中（C_centroid 指标大幅降低），生成的高斯分布更贴合场景几何结构，显著减少了分散的“漂浮”原语。
- **锚点的语义解释性**：学习到的锚点自动形成对场景的**粗粒度空间骨架**，并自适应地分布——在几何/视觉信息丰富的区域密集、在平坦区域稀疏；锚点半径也自适应地调整，在细节区域用较小半径聚焦细节，在弱约束区域用较大半径提供广泛支撑。
- **注意力模式改善**：交叉注意力更聚焦于几何一致的图像区域，减少了纯外观驱动的歧义；自注意力也显示出空间局部化的交互模式。

- **问题定义清晰，动机直观**：精准识别了查询式3DGS的“空间弥散”问题，并将其归因于隐式查询缺乏空间参考，逻辑链条清楚。
- **方法简洁、有效、可解释**：通过引入显式锚点状态，将空间信息无缝注入注意力与解码过程，设计紧凑且各组件均有明确作用。

### 8. 不足与局限

- **假设已知相机位姿**：方法依赖于精确输入位姿（用于计算Plücker射线），无法直接应用于无位姿（pose-free）场景，限制了适用范围。
- **各向同性空间支持**：当前锚点状态为“中心+标量半径”，是各向同性描述。对细长结构或具有空间异质性的几何/视觉信息区域，可能不够精确，无法完全模拟复杂支撑区域。论文承认更丰富的锚点状态（如各向异性）是潜在改进方向。

- **实验覆盖面有限**：直接对比的基线主要是TokenGS；与所有同期方法的广泛比较仍需在完整技术报告中充实。此外，训练资源使用的透明度不足（缺少GPU型号、数量等），可能影响复现实验时的参照性。
